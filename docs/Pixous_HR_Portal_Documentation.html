About This Package

This documentation package covers the complete Pixous HR Portal — a full-stack web application for human resource management, attendance tracking, leave management, payroll processing, real-time chat, and more.

Technology Stack: React 19 + TypeScript (Frontend) · Spring Boot 3.5 + Java 17 (Backend) · MySQL (Database) · Redis (Cache) · Kafka + WebSocket/STOMP (Real-time) · Flutter (Mobile)

Version: 1.0.0 · Date: August 2026 · Classification: Confidential

Modules: 25 backend modules · 37 web pages · 62 mobile screens · 152+ API endpoints

5. Core Module Workflows

5.1 Authentication Flow

Flow: Login → JWT Access Token + Refresh Token → Stored in Secure Storage → Auto-refresh on 401 → Role Detection → Dashboard Routing

Endpoints: POST /api/auth/login · POST /api/auth/refresh · POST /api/auth/logout · GET /api/auth/me · POST /api/auth/change-password

Security: Passwords hashed with BCrypt · JWT with expiration · Refresh token rotation · Session invalidation on logout

5.2 Attendance Flow

Punch In: Employee clicks "Punch In" → GPS coordinates captured → Optional face verification → Backend validates location against office radius → Timestamp recorded → WebSocket notifies team

Punch Out: Employee clicks "Punch Out" → Duration calculated → Hours worked recorded → Real-time status update → Dashboard refreshes

Team View: TL/HR sees team present/absent/late in real-time → Color-coded cards → Date range filtering → Export capability

5.3 Leave Management Flow

Apply: Select leave type → Choose dates → System calculates working days → Balance preview → Submit → Notification to approver → Real-time status tracking

Approve/Reject: Approver sees pending queue → Reviews request → Approves or rejects with mandatory comment → Employee notified → Leave balance updated → Calendar updated

Permission (Short Leave): Apply for 1-4 hours → Approver decision → Duration tracked separately from full-day leave

5.4 Payroll Flow

Request: Employee requests payslip for month → HR reviews → HR generates payslip with earnings/deductions → Company logo optional → PDF generated → Sent to employee

Payroll Run: HR initiates payroll run → System processes all employees → Calculation engine applies rules → Approval workflow → Payslips generated in bulk

5.5 Chat & Real-Time Flow

WebSocket/STOMP: Connect → Authenticate → Subscribe to /topic/chat/{id} · /topic/notifications · /topic/presence → Send messages via /app/chat/send

Features: Direct messages · Group channels · Communities · Reactions · Polls · Voice notes · File attachments · Typing indicators · Read receipts · Pinned messages · Message search · Unread counts

Presence: Online/offline status via STOMP heartbeats · Last seen tracking · Team presence indicator

7. Real-Time Communication Architecture

Protocol: WebSocket with STOMP sub-protocol over SockJS

Topics:

  • /topic/chat/{channelId} — Chat messages per channel
  • /topic/notifications/{userId} — Personal notifications
  • /topic/presence — Online/offline status
  • /topic/tasks — Task updates
  • /topic/attendance — Live attendance feed

Kafka: Used as message broker for event-driven architecture. Events: LEAVE_APPLIED, LEAVE_APPROVED, ATTENDANCE_PUNCHED, TASK_ASSIGNED, PAYROLL_GENERATED

8. Recommendations
  1. Scale to 500+ concurrent users: Consider horizontal scaling with multiple backend instances behind a load balancer.
  2. Database indexing: Add composite indexes for frequently queried date-range endpoints.
  3. CDN for file uploads: Serve uploaded files through a CDN rather than directly from the application server.
  4. Redis eviction policy: Set maxmemory-policy to allkeys-lru for predictable memory usage.
  5. API pagination: Enforce max page size of 100 records to prevent accidental over-fetching.

  • Forms: React Hook Form + Zod validation
  • Real-time: STOMP.js client for WebSocket communication
