## Findings

### F-1 — Employee documents are downloadable without logging in

**Severity: Critical. Priority: P0.**

`SecurityConfig.java:72` places `/api/files/**` in the `permitAll()` list.

*Reproduction:* obtain or guess any stored file path, then request
`GET /api/files/<path>` with no `Authorization` header. The file is returned.

*Expected:* 401 for an anonymous caller; 403 for a caller who is not entitled
to that file.

*Actual:* 200 with the file body.

*What is exposed:* payslips, Aadhaar scans, bank documents, TA petrol slips,
and profile photographs. For 62 users.

*Root cause:* the entry was almost certainly added so that `<img src>` tags
would render without attaching a token. That is a real problem, but the fix for
it is a signed short-lived URL, not opening the whole namespace.

*Recommended fix:* remove `/api/files/**` from `permitAll()` and require
authentication. If inline images then break, issue per-file signed URLs with a
short expiry. Path-based obscurity is not access control — the paths appear in
API responses that many roles can read.

*Regression risk:* medium. Every screen that displays an uploaded image needs
checking after the change.

### F-2 — No rate limiting anywhere, including login

**Severity: High. Priority: P0.**

No rate-limiting dependency or filter exists anywhere in the backend; a search
for `RateLimit` and `bucket4j` returns nothing.

*Reproduction:* POST `/api/auth/login` repeatedly with wrong passwords. Nothing
slows down, nothing locks, nothing is recorded as suspicious.

*Expected:* progressive delay or lockout after a small number of failures, and
a per-IP ceiling on authentication attempts.

*Actual:* unlimited attempts at full speed.

*Why this compounds:* `users.password_vault` stores recoverable passwords by
design. An unlimited-guess login endpoint in front of a database that holds
recoverable passwords means one successful guess of one admin account exposes
every password in the company.

*Recommended fix:* a per-IP and per-username limiter on `/api/auth/**` before
release. Bucket4j is the usual choice for Spring Boot.

### F-3 — Twilio credentials are committed to the repository

**Severity: High. Priority: P0.**

`application-dev.yml:23-24` contains a literal Twilio account SID and auth
token. The file's own comment says not to commit real secrets; the secrets are
committed directly beneath it.

*Recommended fix:* rotate the token in the Twilio console — this is the only
step that actually helps, because the old value is in git history permanently —
then move both values to environment variables.

*Note:* the same file's JWT secret is a documented dev-only fallback and
`application.yml` requires `APP_JWT_SECRET` with no default in production. That
one is fine.

### F-4 — Zero backend tests

**Severity: High. Priority: P1.**

`find backend/src/test -name "*.java"` returns 0 files.

Everything verified about the backend in this project was verified by calling
it by hand. That works once. It does not survive the next change, and there is
nothing to run in CI.

*Recommended fix:* start with tests over the things most expensive to get
wrong: tenant isolation, the payroll visibility guard in
`PayrollController.maySeeEveryonesPay()`, and the `UserService.findUser()`
cross-company check. Spring Boot's `@SpringBootTest` with Testcontainers for
MySQL fits this stack.

### F-5 — Twenty-connection database ceiling

**Severity: Medium. Priority: P1.**

The hosting account permits twenty connections in total. This is not a defect
in the code, but it is a hard scalability limit that has already shaped two
design decisions (the 30-second polling interval on the tech-admin user list,
and fetching a calendar month in one request rather than per day).

*What it means for load testing:* concurrency above roughly twenty simultaneous
active requests will queue or fail, regardless of application performance.
Any load test should be interpreted against that ceiling.

### F-6 — Unused model left in the mobile codebase

**Severity: Low. Priority: P3.**

`flutter_app/lib/models/work_items.dart` defines `WorkReport`, which nothing
references. I added it while starting the work-reports screen and stopped when
asked to. It compiles and analyzes clean, and it is a head start if that screen
is picked up later, but it is dead code today.
